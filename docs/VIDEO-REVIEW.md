# 视频审核后上传视频号草稿

当前顺序：制作 → MP4 文件与完整文案送审 → 用户看完确认 → 上传视频号草稿 → 返回详细结果。不再要求视频号后台手机预览二维码。OK 只授权保存草稿，公开发布需要另行明确指令。

## 送审内容

在 jobs/C编号/vN/video-metadata.json 写实际上传内容：

```json
{
  "title": "准备上传的视频标题",
  "description": "准备上传的完整视频简介",
  "account": {"id": 7, "name": "目标视频号名称"}
}
```

示例 id 不能用于真实账号。目标账号应从已登录账号查询结果选择。build 将此文件加入 manifest；修改已送审文案或视频必须 revise，不能沿用旧确认。

deliver 将视频名、完整简介、目标视频号、版本和文件名发到当前入站来源会话，并发送真正的 MP4 file 附件。长文案分段发送。视频较大时保留原片，发送完整时长传输副本。公众号文章另附实际官方草稿预览链接。

## 确认与上传

建议回复 `OK C0001-v1` 或 `确认上传 C0001-v1`。同会话恰好一个未确认当前视频时支持单独 OK；有多个待审视频必须带版本。视频的“通过 C0001-v1”同样只授权上传草稿。纯文章“通过”保持原审核语义。

路由核对真实入站消息、来源会话、确认时间、当前版本、文案和视频哈希、实际 file 发送成功回执。跨会话、未发出文件、旧版本和内容变化均不生成上传授权。

确认生成 video-draft-approval.json，含真实来源凭据、目标账号、标题、简介、manifest/video/metadata 哈希、syncDraft:true、public_publish_authorized:false 和 published:false，再把 draft_request 交给原 Codex 执行器。重复确认不重复执行；历史授权文件不自动转成新任务。

执行器核对同一内容，通过 TurboPush MCP publish_video 指定 syncDraft:true。查询已有本地内容和远端记录以避免重复；本地 create_video 或 turbopush_local.py 只表示保存内容库。上传后用 list_records/get_record_info 查真实结果，结果不明保留记录并查询，不盲目重试。实际工具策略仍适用。

## 返回格式

- 视频名：实际上传 title
- 视频简介：完整 description
- 目标视频号：账号名及可用账号 id
- 版本与文件：C编号-vN、C编号-vN.mp4
- 草稿上传：成功 / 失败 / 结果待核对
- 远端记录号：实际返回的记录号；没有则说明尚未取得

仅成功记录支持“已上传草稿箱”。OK 不触发公开发布，公众号仍用真实官方文章预览送审。

## 验证范围

Windows 离线测试覆盖真实文件发送回执要求、来源会话和版本绑定、完整文案、长消息不截断、草稿授权及重复确认。测试使用临时文件和模拟企业微信/TurboPush 客户端，没有向用户发送消息或执行真实远端上传，未在 Linux 实机运行验证。
